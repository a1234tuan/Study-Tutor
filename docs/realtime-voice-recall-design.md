# Real-time 语音主动回忆接入设计方案

> 状态：v1.0 产品与技术边界冻结；P0 设计问题已关闭，可进入阶段 0/1 开发，量产默认链路须通过 Provider 与真机验收  
> 编写日期：2026-09-08  
> 适用端：Web、Windows Desktop、Android  
> 产品边界：学习日志仍是记录入口，语音通话是复习与主动回忆媒介，不升级为独立聊天中心。

### 审查修订记录（2026-09-08）

本版已按当前 schema 20、Review Coach 正式事实边界、App 导航与备份实现修正。关键更正如下：

- 新增本机表改用 **schema 21**，不复用已经发布且用于 `reviewAnnotationDrafts` 的 schema 20。
- “保存为日志草稿”改为先进入现有快速创建/主题模板确认；用户确认后才创建正式记录壳并进入编辑器，确认前不产生孤立草稿。
- 第一阶段明确为实时**语音**主动回忆，不宣称已经提供视频通话；摄像头/屏幕视觉上下文另列后续阶段。
- Provider 型号、音色、免费额度和预算改为部署验证快照，不作为产品常量或数据模型默认值。
- Provider 传输改为协议无关适配器；SSE、WebSocket、HTTP chunked stream 或原生 SDK 均由适配层选择。
- 中断改为会话、活动轮次、单请求和播放代际四层取消，避免旧音频在打断后重新入队。
- 明确 App 级运行态、轻量导航来源和 schema 21 检查点的职责；大段转写和音频不得进入 `TabMemory`/`history.state`。
- 明确 local-only 会话在云同步、普通重启、完整恢复、卸载和换机时的不同生命周期。

第二轮审查进一步冻结以下决定：

- 临时会话检查点与用户主动保留的“本机通话历史”使用不同 store 和清理策略；需要备份/换机时必须整理为正式日志。
- Coach 第一版严格采用“一题一条正式回答”，任何追问都不得覆盖已经提交的 `AdaptiveQuizTurn.answerText`。
- 自动轮次、长按说话、点击录音是互斥模式；主按钮按当前模式和状态改变语义，不叠加点击/长按手势。
- `userMuted` 与 TTS 的 `systemCaptureGate` 分离，系统恢复监听不得取消用户静音。
- 内置 Provider 使用可更新、可验证、带版本号的模板；凭据、用户覆盖和自定义 endpoint 保持 device-local。
- 所有费用和用量只显示本机估算，Provider 账单/控制台是最终依据。
- Web 首版不承诺与 Desktop/Android 等价，只允许 Mock、自建中继或经验证支持浏览器直连的 Provider。
- 用户开始前可查看内容外发清单；日志内容始终按不可信输入处理，不能覆盖系统教学规则或触发工具指令。

## 1. 结论

现有信息已经足以冻结产品定位、入口结构、核心交互、数据边界和协议无关的 Provider 抽象，并开始交互原型与技术验证。不需要继续停留在抽象讨论阶段。第一阶段交付的是实时语音主动回忆，不包含摄像头视频或屏幕画面传输，因此不能对外称为“视音频通话”。

仍有四项必须通过真实接口验证，但它们是实施阶段的技术门槛，不阻塞本方案成立：

1. 豆包流式 ASR 在 Android 与 Electron 主进程中的鉴权、音频帧格式和断线重连行为。
2. Fish Audio `s2.1-pro-free` 配合指定音色时的流式首包延迟、分片格式、并发和免费模型限制。
3. `deepseek-v4-flash` 对短回答、流式输出、结构化评估和长会话摘要的真实稳定性。
4. Android 真机上的回声消除、蓝牙耳机、音频焦点、来电打断、后台切换和弱网恢复。

推荐采用已经讨论确认的串联方案：

```text
麦克风
  -> 本机音频预处理与说话状态检测
  -> 流式 ASR
  -> 句段合并与轻量转写整理
  -> 教学型 LLM
  -> 流式 TTS
  -> 扬声器或耳机
```

这不是端到端语音模型，也不是“实时模型负责说话、另一个模型暗中评分”的双脑混合架构。它只有一条清晰主链，ASR、LLM、TTS 可独立替换，学习状态由本地规则和现有 Review Coach 正式事实控制。

## 2. 当前学习闭环与接入判断

### 2.1 当前 APP 已有的两条复习链

第一条是记录级间隔复习：

```text
记录日志
  -> 加入复习
  -> FSRS 安排整条日志的下次复习日期
  -> 用户回看并进行“忘记 / 模糊 / 良好 / 轻松”评分
  -> 写入 RecordReviewLog
  -> 更新 RecordReviewState
```

第二条是决策块级 Review Coach：

```text
标记复习重点（DecisionBlock）
  -> 复习时写下真实卡点
  -> 快速模型整理反馈
  -> 用户确认后进行深度分析
  -> 生成 SessionBlueprint
  -> 本地调度 AdaptiveReviewTask
  -> 自适应提问、作答、提示和结果记录
  -> 安排 DelayedVerification
  -> 以保持/衰退结果更新可重建的效果投影
```

两条链必须继续独立：整条日志评分只影响记录级 FSRS；决策块回答和延迟验证只形成 Coach 事实，不能偷偷改写整条日志的复习时间。

### 2.2 语音功能的正确定位

语音通话不是第三套学习系统，而是两类现有学习动作的新执行媒介：

- 在日志复习中，它帮助用户闭卷复述，但不会替用户完成记录级评分。
- 在 Review Coach 中，它替代键盘成为回答方式，沿用 Blueprint、题目质检、答案评估、结果事件和延迟验证。
- 在没有本地资料时，它提供自由主题的发散回顾，但默认不制造“已掌握”事实。

因此产品名称建议使用“语音复述”，通话页内可以使用“语音学习”或“和学习教练对话”。不建议把入口叫作“Real-time”“语音模型”或“AI Call”。

## 3. 一个入口，两种起始模式

不创建两套彼此割裂的入口和通话页面。保留同一个规范目的地，在开始页提供二级模式选择：

### 3.1 从学习资料开始

复用现有 `AiKnowledgeScope` 和知识范围选择能力：

- 单条或多条指定日志。
- 某个学科与标签。
- 最近 7、14 或 30 天。
- 某一天的日志。
- 从当前日志、当前复习卡或当前 Coach 任务直接进入时，自动范围由来源确定，无需再选一次。

开始前增加“知识边界”选择：

- **以日志为主，允许教材补充（默认）**：题目以用户资料确定主题和学习目标，AI 可以补充标准术语、常见前置知识、典型例子与纠错信息。
- **严格依据日志**：回答和题目只使用选定资料，资料不足时明确说明，不向外扩展。
- **主题拓展**：从日志主题出发进行更广的迁移、比较和应用练习。

AI 输出必须区分“你的日志中写到”和“补充知识”。补充内容不能伪装成日志原文，也不能自动改写日志；当外部常识与日志冲突时，先指出差异并让用户判断。

### 3.2 自由主题

用户直接输入或说出主题，例如“帮我复述行政法的比例原则”或“随机检查我对操作系统进程调度的理解”。可以补充选择：

- 本次目标：复述、查漏、辨析、迁移应用或开放讨论。
- 熟悉程度：刚学、复习中或考前检查。
- 期望时长：5、10、20 分钟。

自由主题不要求存在本地日志，不进入记录级 FSRS，也不直接创建 Review Coach 的掌握或延迟验证事实。结束后提供三个明确选择：不保留、保留为本机通话历史、整理为日志。

- “保留为本机通话历史”只保存摘要和必要来源信息，不保存原始音频或完整逐字稿；首次使用明确提示“仅保存在此设备，不进入云同步或备份，卸载、清除数据或换机后无法恢复”。
- “整理为日志”是需要进入正常备份/同步范围时的正式路径。选择后先打开现有快速创建/主题模板确认界面；只有用户确认创建时才调用现有记录创建路径并持久化记录壳，随后进入编辑器。此后的未保存编辑由现有 `RecordDraft` 保护；确认前取消不创建任何记录或孤立草稿。

### 3.3 为什么不拆成两个独立功能

两种模式共享麦克风、轮次管理、教师策略、转写、TTS、异常恢复和通话界面。拆成两套入口会制造重复设置与历史，也会让用户误以为自由对话同样能更新正式学习状态。

最终采用“一个规范页面 + 多个上下文快捷入口”：入口来源不同，但都打开同一页面和同一份会话状态。

## 4. 导航与入口设计

### 4.1 规范入口

将“语音复述”放在 `复习` 首页，和“日志复习”“学习助教”“卡片库”处于同一学习域，但不新增全局一级导航。

推荐布局：

- 复习首页的首要操作仍是“开始今日复习”。
- 在首要操作旁提供清晰可见的“语音复述”按钮，使用麦克风图标和文字，不藏入更多菜单。
- “学习助教”任务存在时，任务行提供“语音回答”，直接进入任务绑定会话。
- 卡片库和日志详情提供可见的麦克风图标操作，分别带入当前卡片或日志范围。
- “更多”中的 AI 工具区可保留一个次级快捷入口，但打开的仍是同一规范页面。

不建议把它加入 Desktop 左侧一级导航或 Mobile 底栏。当前用户可见的五个一级入口是“今天、日志、复习、录音、更多”；其中“录音”内部映射到 `more/recordings`，`categories` 是分类管理的内部 TabKey/次级入口，不应写成用户可见一级导航。增加一个常驻 AI 入口会再次削弱“记录与复习”的产品定位。移动端中央新建按钮也继续只负责创建日志，不复用为语音入口。

### 4.2 条件式入口

“今天”页只在有明确学习上下文时显示一行轻量建议，例如：

- 有到期复习：“先用 5 分钟口述今天最重要的一条”。
- 刚保存含决策块的日志：“趁记忆清晰，试着不看笔记讲一遍”。
- 有到期延迟验证：“用语音完成这次延迟检查”。

没有明确动作时完全不占首页空间，不使用长期驻留的大卡片。

### 4.3 返回语义

导航层只保存来源页面、筛选、滚动位置、当前卡片和任务 ID 等轻量身份信息：

- 从日志详情进入，结束后回到同一日志。
- 从日志复习进入，结束后回到同一张卡，且仍需由用户评分。
- 从 Coach 任务进入，结束后回到任务结果页。
- 从复习首页进入，结束后回到复习首页。

系统返回键、页面返回按钮和结束通话后的返回必须遵守同一导航栈，不能统一跳回首页。录音、`finalizing-asr`、`thinking` 或 `speaking` 状态下触发返回时，先弹出动作面板：

- **暂停并离开**：立即关闭采集和播放，保留检查点并返回来源页。
- **结束通话**：结束本次会话，进入结束摘要页；若当前存在未确认转写，先询问丢弃还是保留为本机草稿。
- **继续通话**：关闭面板，不改变当前状态。

系统返回键不得在麦克风活动时无提示退出；只有会话已经暂停且没有未确认内容时，才可直接返回来源页。

活动会话、转写、播放队列和连接对象由 App 级 `VoiceRecallRuntimeController`（或等价 store）持有；可恢复检查点写入 schema 21 的 local-only 表。不得把大段转写、音频或 Provider 对象塞入 `TabMemory`、URL 或浏览器 `history.state`。离开通话页时必须立即暂停麦克风和播放，返回后由用户明确继续。

## 5. 三种会话与业务语义

### 5.1 Coach 任务绑定（`task-bound`）

这是与学习闭环结合最深的模式。语音只是输入输出方式：

- 问题仍由 `SessionBlueprint` 约束。
- 题目展示前仍经过现有质量检查。
- ASR 最终文本写入现有 `AdaptiveQuizTurn.answerText`，与键盘回答使用同一提交路径。
- `TaskOutcomeEvent`、提示使用、题目失效、延期、放弃和延迟验证保持原语义。
- 正式对象最多增加 `answerInputMode?: "voice" | "text"` 与 `transcriptEdited?: boolean`。ASR Provider、模型、置信度、原始转写和诊断属于设备运行信息，只保存在 local-only 轮次数据中，不进入正式学习事实。
- 用户说完不等于自动“已掌握”；答案评估和最终主观自评仍是两个独立事实。

该模式的正式写入必须继续经过 `reviewCoach/repository.ts` 与 `orchestrator.ts`，不能由通话页面直接写 Dexie。

若增加上述两个正式字段，必须同时更新领域校验、repository、正式快照、云映射/哈希、备份兼容和导出隐私测试，不能只修改 TypeScript 接口。

#### 第一版一题一正式回答契约

现有 `AdaptiveQuizTurn` 只有一个 `answerText`，因此第一版不在同一道正式题内实现可反复改写事实的开放式多轮对话。固定流程为：

```text
展示一条正式题目
  -> 用户可在回答前请求现有分层提示（写入 hintsUsed）
  -> 采集一段本机回答草稿
  -> 用户确认/编辑最终转写
  -> submitQuizAnswer 一次性提交并评估
  -> 当前 AdaptiveQuizTurn 变为 answered
  -> 播放评估反馈
  -> 如需追问，由现有生成路径创建 sequence 递增的新 AdaptiveQuizTurn
```

约束如下：

- 回答草稿、ASR partial、自我修正和确认前补充只存在 `VoiceRecallTurnLocal`，不得提前写入正式 turn。
- 用户在提交前请求提示时，保留同一题，但最终提交必须带上完整 `hintsUsed`；不得把提示前的草稿伪装成“无提示答案”。
- `submitQuizAnswer` 成功后，已回答 turn 的 `answerText` 不再拼接或覆盖。教师追问必须创建下一条正式题目；纯口头解释只能作为本机播放/历史内容，不能反写上一题。
- 若评估返回 `insufficient-context` 且正式事务尚未提交，原 turn 仍为 `displayed`，允许用户编辑后以新的幂等操作重新提交；不得产生半条正式答案。
- “再说一点”在提交前表示替换/补充本机草稿；提交后表示开始下一条正式追问，两种状态必须使用不同文案。

### 5.2 日志范围练习（`scope-practice`）

从一条或多条日志开始的临时复述，不要求已有 Coach 任务：

- AI 依据选定范围提问并允许教材补充。
- 会话结果默认只是本机练习记录，不改变 FSRS 或决策块状态。
- 如果用户发现真实卡点，结束页可以把用户确认的一段文字带回当前复习卡的“记录卡点”输入框，或引导到日志编辑器标记决策块。
- 系统不能把整段通话偷换成 `DecisionBlockFeedback`，因为通话可能跨多个块，且用户未必是在描述单一困难。

第一版不新增“语音练习后自动加入 Coach”的隐式规则。后续若需要让非任务语音成为正式学习证据，应另行设计 append-only 的 `VoiceRecallEvidence` 及云同步协议。

### 5.3 自由主题（`free-topic`）

自由主题仅使用用户给出的主题和当前会话上下文：

- 不调用本地日志检索。
- 不更新任何复习状态。
- 可以保留为本机通话历史，或显式选择“整理为日志”。
- 选择后先进入现有快速创建/主题模板确认；确认时创建正式记录壳并进入编辑器，之后由现有 `RecordDraft` 保护未保存编辑。取消确认不产生数据。

## 6. 通话前界面

### 6.1 起始页

顶部显示返回、标题“语音复述”和设置入口。正文采用一个分段控件切换：

- 从学习资料开始
- 自由主题

资料模式复用现有知识范围选择器，但允许单条日志直接开始；当前 AI 问答要求至少选择多条日志的限制不能机械复制到语音复述。自由主题模式提供主题输入、目标和时长选择。

主按钮显示“开始语音复述”。按钮上方只展示影响决策的状态：

- 当前 ASR、LLM、音色以及内置模板版本。
- 麦克风权限与网络状态。
- 预计时长和本机估算费用等级“低 / 中 / 高”。
- 资料缺失、OCR 不完整或 Provider 未配置的警告。

模型、Endpoint、精确 token 和请求参数进入“用量与技术详情”，不占据主界面。

### 6.2 通话前检查

按以下顺序执行：

1. 展示本次内容外发清单并取得确认：麦克风音频发送给 ASR；选中的日志片段与确认后的转写发送给 LLM；教师生成文本发送给 TTS。清单显示 Provider、资料标题/范围、是否经过用户自建中继，以及 Provider 数据保留说明入口。
2. 检查麦克风权限和可用输入设备。
3. 检查 ASR、LLM、TTS 三个 Provider 是否各有可用配置与本机密钥。
4. 计算资料上下文和预计时长，执行单次会话预算门控。
5. 进行短音频设备测试，仅在首次使用、设备变化或上次失败时出现。
6. 预热 ASR 连接；成功后才进入通话页面。

任一环节失败都显示用户可理解的错误和明确动作，原始异常必须经过 `uiError.ts`，不得直接展示 Provider 响应或密钥信息。

日志正文、OCR 文本、标签和历史转写都属于不可信内容。构造 LLM 请求时必须放入明确的数据边界，不得把其中的“忽略规则”“调用工具”“泄露系统提示”等文字当作系统指令；首版语音链不授予日志内容任何工具执行权限。对超出范围的 Provider 外发必须重新确认，不能沿用一次笼统授权。

## 7. 沉浸式通话界面

### 7.1 视觉结构

通话页采用全屏、无卡片堆叠的沉浸布局：

- 顶部：返回、主题、通话计时、连接状态和更多菜单。
- 中央：当前教师问题、一条响应说话状态的水平声波，以及“正在听 / 正在整理 / 正在思考 / 正在回答”。
- 下部：最近一轮实时转写，可展开查看完整对话；默认不让大段文字抢占注意力。
- 底部：静音、主说话按钮、打断/继续、结束通话。

不使用仿真人头像、装饰性光球或持续高负载 3D 动画。面对面感主要来自及时的听说反馈、稳定的轮次节奏、自然音色和教师式回应，而不是伪装成视频人物。

声波使用 Canvas 或轻量 CSS/SVG 实现，限制刷新率并支持 `prefers-reduced-motion`。减少动态时改为静态电平条和文字状态。

### 7.2 双主题

两套视觉主题共享布局和交互：

- **温润阅读（默认）**：暖白工作面、中性深色文字、少量陶土色状态强调；声波不过度饱和。
- **清爽现代**：中性明亮背景、克制绿色强调和更清晰的状态分隔。

深色模式是独立维度，不通过简单反色生成。通话中所有文本、波形、焦点环和错误状态必须满足对比度要求。

### 7.3 Desktop 与 Android

Desktop 将内容限制在适合对话阅读的中央列，设备、转写和来源详情可从右侧抽屉打开；不永久占用空白检查器。

Android 的核心控制固定在系统安全区上方，按钮触控范围至少 44px。完整转写单独滚动，不能推动控制区或被底部导航遮挡；通话时隐藏全局底栏。页面必须适配刘海、手势条、系统字号和横屏。

## 8. 说话控制、静音与噪声

### 8.1 默认交互：自动轮次（半双工）

通话前选择一种互斥输入模式，默认是“自动轮次（半双工）”。通话中只允许在暂停状态切换模式，切换时清空未发送音频但保留已确认文本，避免同一个触控事件同时触发点击和长按语义。

主按钮按模式与状态驱动：

- **自动轮次**：AI 说完后自动聆听；`listening` 时主按钮为“立即发送”，不再承担“点击开始录音”或长按手势。
- **长按说话**：主按钮为“按住说话”，按下才采集，松开即结束并发送；短点击不执行发送。
- **点击录音**：未录音时为“开始说话”，录音中为“发送”；不识别长按动作。
- **AI 回答中**：自动/点击模式的主按钮变为“打断并说话”；长按模式显示“按住打断并说话”，按下即打断、松开即发送。若 `userMuted=true`，按钮明确显示“取消静音并说话”，该操作才可作为用户主动解除静音。
- **处理中**：`finalizing-asr`/`thinking` 时按钮为取消当前轮次，不得伪装成可录音状态。

第一次使用只展示与当前所选模式对应的短提示，不同时教授三套手势。

### 8.2 自我静音

提供独立静音按钮，并将两类门控建模为不同状态：

- `userMuted`：由用户显式控制，跨轮次保持，只有用户再次操作才能解除。
- `systemCaptureGate`：由 TTS 播放、音频焦点、后台或系统打断临时设置；条件消失后只能恢复到 `userMuted` 允许的状态。
- 有效采集条件为 `captureRequested && !userMuted && !systemCaptureGate`。界面必须分别显示“已静音”和“播放中暂停售麦”，不能共用一个布尔值或同一提示。

- 静音后停止向 ASR 发送音频，但保持会话与 AI 播放。
- AI 开始 TTS 时设置系统麦克风门控，避免扬声器声音被再次识别；TTS 结束不得擅自清除 `userMuted`。
- 用户想打断 AI 时，点击“打断”或按住主按钮；系统先停止 TTS，再打开麦克风。
- 高级设置可开启全双工实验模式，但不作为第一版默认。

### 8.3 音频预处理

优先使用系统/WebRTC 能力：

- 回声消除`echoCancellation`
- 噪声抑制`noiseSuppression`
- 自动增益`autoGainControl`
- 采集层输出带 `sequence`、单调时钟时间戳和格式描述的音频帧

本地 VAD 只判断“像不像人声”和辅助显示状态，不能保证识别语义，也无法可靠排除背景讲话。目标是降低汽车鸣笛、摔落声、喷嚏等非语音触发概率；ASR 的噪声鲁棒性作为第二层过滤。第一版必须用固定噪声语料统计误触发率、漏检率和端点延迟，并提供长按/点击模式作为高噪声环境兜底，不能承诺“噪声绝不会创建轮次”。

内部可选用 16 kHz 单声道 PCM 作为规范格式，但不能假定所有 Provider 都接受同一采样率和编码。`VoiceCaptureAdapter` 与 Provider adapter 必须协商能力；不匹配时在明确的重采样/转码层处理，并对质量、耗电和延迟做验收。

## 9. 停顿与一句话结束判定

不能把一次短暂停顿等同于“用户说完”。本地 `TurnEndpointController` 统一决定提交时机：

1. ASR partial 只用于屏幕预览，不触发 LLM。
2. 约 1.8 秒静音后进入“可能说完”状态，而不是立即发送。
3. 如果文本以连接词、未完成枚举、明显半句结束，继续等待，最长可延长到约 4 秒。
4. 用户重新开口时把前后 ASR 片段合并为同一轮。
5. 单轮达到约 45 秒时提示“内容较长，可以继续分段说”，但不截断已识别文本。
6. 点击结束、松开长按或第二次点击主按钮具有最高优先级，立即完成本轮。

时间参数必须可配置并通过真实中文思考停顿语料调校，不能散落在组件内部成为魔法数字。

## 10. ASR 转写整理

第三方 ASR 可以提供标点、数字规范化、热词和部分语气词处理，但不能保证把断续思考自动改写成语义完整且绝不失真的书面答案。因此采用三层策略：

1. Provider 层开启语义标点、逆文本规范化、热词和可用的顺滑输出能力。
2. 本地只做确定性的空白、重复分片和跨停顿句段合并，不自行改写语义。
3. 第一版默认只做确定性整理并允许用户编辑。仅当用户启用、Provider 提供可靠置信度且碎片率或低置信度超过阈值时，才可调用独立的低成本 LLM 预处理角色做一次轻量整理；它不是第二个“隐藏老师”。

LLM 整理必须返回结构化结果：

```json
{
  "cleanText": "整理后的原意文本",
  "uncertainSpans": ["可能识别错误的片段"],
  "meaningRisk": "low | medium | high"
}
```

约束如下：

- 不增加用户没说过的知识结论。
- 不把犹豫自动解释为肯定。
- 专有名词不确定时保留原词并标记。
- `meaningRisk=medium | high` 时必须让用户确认或编辑，不能直接进入答案评估。
- 任何 LLM 改写都必须在提交前可见，不得用整理文本静默替换 Provider final 原文。
- 屏幕上允许点击转写文本快速修正；修正后记录 `transcriptEdited=true`。

当前轮次完成前保留 Provider final 原文和 cleanText。正式提交后，任务绑定模式只保存用户确认使用的答案文本；原始音频和 partial 分片立即释放。

## 11. 教学对话与上下文记忆

### 11.1 教师行为

系统 Prompt 固定以下教学纪律：

- 一次只问一个核心问题，优先让用户完整复述。
- 不因短暂停顿抢答，不替用户补完答案。
- 先追问或给分层提示，再决定是否讲解。
- 指出正确部分、遗漏、混淆和下一步，而不是只说“很好”。
- 回答尽量适合口语播放，避免长列表、Markdown 表格和连续术语堆叠。
- 需要补充教材知识时明确说“补充一点标准表述”。
- 不自行宣告长期掌握，不决定 FSRS 日期或延迟验证日期。

### 11.2 会话记忆

同一次通话有上下文记忆，但不能承诺无限不忘。沿用现有 AI 聊天的“最近轮次 + 压缩摘要”思路，并为语音增加结构化会话状态：

- 当前学习目标与来源范围。
- 已经回答过的关键点。
- 已确认的正确结论与待纠正误区。
- 已用提示和仍未覆盖的 Blueprint 判据。
- 用户要求稍后回到的话题。
- 下一问目的。

最近若干轮原文与结构化摘要一起发送给 LLM。摘要更新必须可校验，不能覆盖正式作答事实。不同通话默认不共享自由对话记忆；Coach 任务通过正式 Blueprint 和历史结果延续，而不是把所有聊天全文不断塞回模型。

## 12. ASR、LLM、TTS Provider 设计

### 12.1 候选默认链路与版本化模板

```text
豆包/火山引擎流式 ASR
  -> DeepSeek deepseek-v4-flash
  -> Fish Audio s2.1-pro-free
```

Fish Audio 当前测试音色：`5c353fdb312f4888836a9a5680099ef0`。

豆包 TTS 备用预设：

- 模型/Resource ID：`seed-tts-2.0`
- 音色：`zh_female_yingyujiaoxue_uranus_bigtts`

阿里云备用预设：

- 低成本流式 ASR：`paraformer-realtime-v2`
- 质量对照 ASR：`qwen-audio-3.0-asr-flash-streaming`
- TTS：`qwen-audio-3.0-tts-flash`
- 可选音色 TTS：`cosyvoice-v1`

系统 TTS 只作为无第三方 TTS 时的应急降级，不作为推荐音色。

以上链路是开箱配置的**候选默认预设**，不是取消默认 Provider。实施采用可更新、可验证的版本化内置模板，例如 `voice-default-cn@1`：模板包含 Provider 类型、公开 endpoint 模板、模型/Resource ID、推荐音色、协议能力声明、最低 App 版本和验证日期，但不包含任何凭据。

型号、音色、流式能力、并发、区域可用性和计费信息必须在阶段 0 通过控制台与真实 API 复核，验证通过后才把该模板版本标记为 `verified` 并作为默认推荐。运行时连接测试或能力探测失败时，不得静默改写用户配置，应提示更新模板、选择备用模板或进入文字模式。现有源码中的 TTS 模板仍以 `s2.1-pro-free`、`qwen3-tts-flash` 和 `seed-tts-2.0` 为兼容基线；候选新型号需通过显式模板版本和迁移处理。

### 12.2 配置抽象

新增彼此独立的配置：

```typescript
interface VoiceProviderTemplate {
  templateId: string;
  version: number;
  status: "candidate" | "verified" | "deprecated";
  verifiedAt?: string;
  minimumAppVersion: string;
  asrProfileId: string;
  llmProfileId: string;
  ttsProfileId: string;
}

interface AsrProviderProfile {
  id: string;
  providerId: "doubao" | "aliyun-bailian" | "openai-compatible" | "custom";
  providerName: string;
  endpoint: string;
  transport: "websocket" | "sse" | "http-stream" | "native-sdk";
  model?: string;
  resourceId?: string;
  language: string;
  acceptedSampleRates: number[];
  acceptedFormats: Array<"pcm-s16le" | "opus" | "aac" | "provider-native">;
  punctuation: boolean;
  inverseTextNormalization: boolean;
}

interface VoiceCallConfig {
  templateRef?: { templateId: string; version: number };
  asrProviderId: string;
  llmProviderId: string;
  ttsProviderId: string;
  inputMode: "auto-half-duplex" | "push-to-talk" | "tap-to-record";
  maxSessionMinutes: number;
  defaultKnowledgePolicy: "notes-plus" | "notes-only" | "expand";
}
```

LLM 继续引用现有 `AiProviderProfile`，不复制一套 DeepSeek Key。TTS 扩展现有 `TtsProviderProfile`，增加 endpoint、流式能力、音频格式和首包超时，同时保持知识播客旧配置可迁移。

豆包可能需要 App ID、Access Token 和 Resource ID，传统二字段 `AiSecret` 不足以表达所有供应商。新增 Provider 专用的本机凭据记录或原生安全存储引用；界面按 Provider 显示必要字段，不能把账号字段塞进普通模型配置。

配置同步边界冻结如下：

- App 随签名版本发布的内置模板是公开产品资源，以 `templateId + version` 标识，不依赖用户云同步。若以后支持远程模板清单，清单必须进行应用内置公钥签名校验；Provider 或 endpoint 变化必须向用户展示并重新确认，不能仅依赖 HTTPS 静默替换。
- 密钥、Token、App ID、签名材料、自定义 endpoint、用户选择的模型/音色覆盖、区域和设备路由全部 device-local，不进入 Firebase、备份或正式学习事实。
- 本机会话可记录实际使用的 `templateId + version` 与非敏感能力快照用于诊断，但不得写入 `AdaptiveQuizTurn`。
- 第一版不提供“跨设备同步 Provider 配置”。后续若要同步，只允许经过白名单校验的无密钥公开模板引用，必须另行设计冲突和隐私协议。

### 12.3 密钥与传输

- 密钥、Token、App ID 与签名材料仅保存在设备本机，不进入 Firebase、ZIP、流式备份、日志或截图。
- Android 优先使用 Keystore，Windows 优先使用 Electron `safeStorage`。
- Web 首版只允许确定性 Mock、自建中继，或经过 CORS、浏览器鉴权和密钥暴露审查后明确标记 `browserDirectSupported` 的 Provider。无法避免长期密钥进入页面脚本的 Provider 禁止浏览器直连；Web 不承诺与 Android/Desktop 的 Provider 覆盖和延迟等价。
- 需要自定义签名头和长连接的 ASR/TTS 由 Android 原生插件或 Electron 主进程代理，不把长期密钥暴露给页面脚本。
- 开源仓库、自动化测试和预览只使用确定性 Mock Provider。

当前 Android `NativeAudioRecorder` 只能开始/停止并返回完整 M4A 文件，无法满足实时 PCM 帧传输。必须新增独立的 `NativeVoiceCapture` 流式插件，不能在现有录音库插件上硬加互相冲突的状态。

## 13. 低延迟流水线

### 13.1 LLM 流式输出

现有 `aiClientService.ts` 使用非流式 `fetch` 并等待完整 JSON。语音功能需新增协议无关的流式 adapter contract，但保留原接口供结构化评估和普通 AI 功能使用。上层只消费 `token/audio/asr/error/completed` 等异步事件，不感知底层是 SSE、WebSocket、HTTP chunked stream 还是原生 SDK；不得把 SSE 写进领域 orchestrator。

推荐流程：

```text
LLM token delta
  -> 句界缓冲器
  -> 得到首个可朗读短句
  -> TTS 流式请求
  -> 音频抖动缓冲
  -> 播放
  -> 后续句子并行排队
```

第一句不等待整段回答生成完。句界缓冲必须保护数字、缩写、公式和英文术语，避免在错误位置切句。

### 13.2 打断

取消必须分层管理：

- 会话级 controller 负责结束整场会话。
- 活动轮次级 controller 负责打断当前 ASR/LLM/TTS 链。
- 每个 Provider 请求有独立 controller，并与上级 signal 关联。
- 播放队列使用递增 generation/token；只有当前 generation 的异步结果可以入队。

- 用户打断时停止当前音频、取消后续 TTS 队列，并尽可能取消 LLM 流。
- 已经播放的内容记录到本机轮次状态，未播放草稿不成为正式事实。
- 打断后立即进入聆听，不把扬声器尾音识别成用户回答。
- 即使 Provider 不支持真正取消，晚到的旧 generation 结果也必须被丢弃，不能重新开始播放。

## 14. 状态机与恢复

通话主状态固定为：

```text
idle
  -> preflight
  -> connecting
  -> listening
  -> finalizing-asr
  -> thinking
  -> speaking
  -> listening
```

旁路状态包括 `paused`、`reconnecting`、`ending` 和 `failed`。静音不再作为混合旁路状态，而是正交的 `userMuted` 与 `systemCaptureGate`；任何时刻最多只有一个活动轮次和一个当前 generation 的 TTS 播放队列。

状态所有权分三层：App 级 runtime controller 持有活动连接、播放器与内存队列；导航状态只持有来源身份；schema 21 保存可恢复检查点。组件卸载不能等同于会话结束，但必须触发采集/播放暂停。恢复时只重建可幂等恢复的文本和操作，不恢复未确认的原始音频。

恢复规则：

- 切换 APP 内 Tab：未结束会话保留，返回后恢复同一页面和状态；麦克风默认暂停，避免后台偷录。
- APP 进入后台、锁屏或失去音频焦点：暂停采集与播放，保留本机会话检查点。
- 网络中断：停止提交新轮次，显示重连；未确认音频最多短暂缓冲，超时后要求重说。
- 重试使用 `sessionId + turnId + operationId` 幂等键，不重复提交回答或播放两遍。
- 用户明确结束后释放麦克风、WebSocket、播放器和临时音频。

## 15. 本地存储、云同步与隐私

### 15.1 第一版新增本机数据

在 **schema 21** 增加 local-only store；schema 20 已由 `reviewAnnotationDrafts` 使用，不得修改已发布版本的 store 定义：

- `voiceRecallSessions: "id, status, updatedAt, sourceKind"`，row type 为 `VoiceRecallSessionLocal`：保存入口来源、范围引用、当前状态、Provider 非敏感元数据、结构化记忆和恢复检查点。为可索引性将 `sourceKind` 保持为顶层字段。
- `voiceRecallTurns: "id, sessionId, [sessionId+sequence], status, updatedAt"`，row type 为 `VoiceRecallTurnLocal`：保存问题、最终转写、整理文本、播放完成范围和错误状态；`sequence` 在同一 session 内单调递增且不得复用。
- `voiceRecallLocalHistory: "id, savedAt, sourceKind"`，row type 为 `VoiceRecallLocalHistory`：只保存用户主动保留的标题、摘要、来源引用和本机估算用量，不保存原始音频、完整逐字稿、Provider 原始响应或可恢复运行态。

三个 store 都不加入 `CloudSyncEntityType`，不进入 Firebase、ZIP、流式/native backup、知识导出或记录转移；写入时不得标记 cloud mutation。原始音频帧、ASR partial、TTS 音频分片和 Provider 原始响应只存在内存或短期临时文件，轮次提交或会话结束后清理。第一版不提供“保存整段通话录音”；未来若增加，必须另行设计本机资产、备份/同步、授权与保留策略，不能直接复用普通 Asset 流程造成隐式上传。

临时与主动保留数据使用不同生命周期：

- `voiceRecallSessions`/`voiceRecallTurns` 是可恢复临时检查点。必须定义单轮/单会话转写上限、检查点节流、失败写入重试、崩溃后 `active -> interrupted` 修复和已结束临时会话保留天数；超限时先删已结束临时会话。
- `voiceRecallLocalHistory` 仅在用户明确选择“保留为本机通话历史”时创建，不参与临时缓存自动清理；仅由用户删除、存储管理中的明确清理动作或应用数据被清除时删除。
- 两类数据都不能影响或删除正式 Coach 事实。需要可备份、可换机的摘要必须走“整理为日志”，不能把本机历史升级为隐藏的半正式事实。

### 15.2 可以同步的既有正式事实

仅任务绑定会话复用现有正式数据：

- `AdaptiveQuizTurn.answerText`
- 已展示问题和提示使用
- `TaskOutcomeEvent`
- `DelayedVerification`

仅 `answerInputMode` 和 `transcriptEdited`（若最终决定加入）随对应正式对象同步。ASR Provider/模型、置信度和运行诊断保持 local-only，不包含原始音频、partial、密钥、完整 Prompt 或 Provider 原始响应。

### 15.3 明确禁止的隐式写入

- 自由主题通话不能自动创建日志。
- 日志范围练习不能自动评分 FSRS。
- 一次语音回答不能自动宣告决策块长期掌握。
- 补充的教材知识不能自动写回用户日志。
- 切换 Provider 或设备不能制造正式数据冲突。

schema 21、备份恢复、记录删除、云实体白名单和 no-op 同步必须一起测试。local-only 表绝不能因为一次云端拉取或冲突合并而被清空。

生命周期必须采用以下明确语义：

- App 内导航、页面卸载和普通 App 重启：保留未完成会话检查点，恢复时保持暂停并要求用户确认继续。
- 云拉取、云冲突处理和 no-op 同步：保持 local-only 会话不变。
- 完整备份恢复：默认清除 `voiceRecallSessions`/`voiceRecallTurns`，避免旧运行态与恢复后的正式数据错配；默认保留 `voiceRecallLocalHistory`，但对已经不存在的来源只显示“来源不可用”，不得恢复正式提交能力。恢复界面必须明确说明该历史不来自备份。
- 普通应用版本升级在数据库迁移成功时保留 `voiceRecallLocalHistory`，但不把“覆盖安装”宣传为备份能力。
- 卸载、清除应用数据或换机恢复：本机通话历史无法恢复；便携备份中没有这些数据。首次保存和本机历史页都持续显示该边界。
- 删除被引用的日志、Coach 任务或记录时，相关未完成本机会话转为 `interrupted` 并标记 `sourceUnavailable`，不得保留一个仍可提交正式答案的悬空会话；是否随即删除由统一清理策略决定。

## 16. 成本与限额

以下额度与日期是 2026-09-08 当前测试账号的部署验证快照，不是产品保证，实施和发布前必须在 Provider 控制台复核：

- `paraformer-realtime-v2`：36,000 秒。
- `qwen-audio-3.0-asr-flash-streaming`：36,000 秒，2026-10-27 到期。
- `qwen-audio-3.0-tts-flash`：10,000 字符，2026-10-12 到期。
- `cosyvoice-v1`：10,000 字符。

当前测试账号费用中心记录为 10 元/月预算、实际消费超过 5 元提醒。它是部署运维配置，不得写入产品默认值或数据库迁移。预算只提醒，不是账户总硬停；任何“免费额度用完即停”也必须通过真实账号行为验证。

应用内再增加：

- 默认单次通话 10 分钟，上限 20 分钟，可由用户调整。
- 本机估算达到时长或费用阈值 80% 时语音和视觉提醒。
- 达到本机软阈值时在开启下一轮前提醒。达到本机请求门控上限时，在安全边界阻止新的 LLM/TTS 请求，保留已确认答案并切换为文字结束摘要或直接结束；已被 Provider 接收、重试或延迟记账的请求仍可能产生费用，因此它不是账户级硬限额。
- 通话前显示“预计消耗低/中/高”，详情显示预计 ASR 秒数、TTS 字符和 LLM token。
- 通话结束显示本机采集时长、发送/接收量和估算费用，并标注“仅供参考，以 Provider 账单为准”。客户端不得断言失败调用一定不计费；只显示请求状态和本机是否收到可计量响应。
- 每个 Provider 独立超时、最大重试和熔断，禁止无限重连或无限重生成。

当前个人低频阶段不购买 NLS 商用资源包或百炼节省计划。先用免费额度采集真实分钟数和字符数，再决定是否购买。

## 17. 错误与降级

- ASR 不可用：保留当前问题，允许切换为键盘回答，不改变任务状态。
- LLM 不可用：保留已确认转写，允许稍后重试；不生成虚假评估。
- TTS 不可用：展示文字回答并尝试系统 TTS，用户可继续文字模式。
- 麦克风权限被拒：解释系统设置路径，并提供键盘继续。
- 转写置信度低：显示可编辑文本，不自动提交。
- 内容上下文过大：按现有检索预算选择相关片段，显示遗漏说明，不静默截断关键决策块。
- Provider 返回原始错误：记录脱敏诊断，用户界面只显示归一化错误和下一步操作。

任何降级都不能改变评分、任务完成或延迟验证语义。

## 18. 分阶段实施

### 阶段 0：接口契约与隔离原型

- 冻结本方案中的状态机、业务边界和协议无关的 Provider 接口；Provider 型号和账号额度只作为待验证配置。
- 制作 Desktop/Android 双主题可交互通话原型。
- 用 Mock 音频展示聆听、停顿、整理、思考、播放、静音、打断、错误和重连。
- 验收入口权重、内容外发清单、三种互斥输入模式、返回/结束确认、底部安全区、大字号和减少动态。
- 对每个候选 Provider 实测协议、鉴权、输入格式、流式首包、取消、并发、配额与错误格式；未通过者不得进入量产默认链路。
- 将通过验证的候选链路发布为带 `templateId + version + verifiedAt` 的内置模板，不把账号特有额度写入模板。

### 阶段 1：音频与轮次底座

- 建立 `VoiceCaptureAdapter`、`TurnEndpointController`、播放队列和音频焦点管理。
- Android 新增流式 PCM 插件；Electron 建立主进程音频/网络桥接。
- 使用录制语料和确定性 Mock ASR 验证停顿、噪声、长句和幂等恢复。
- 实现 App 级 runtime controller、`userMuted`/`systemCaptureGate`、分层取消、播放 generation 和 schema 21 三类 local-only store。

### 阶段 2：三类 Provider 接入

- 豆包 ASR 主接入，阿里云 Paraformer 备用。
- DeepSeek 流式 LLM，并保留 OpenAI-compatible 自定义配置。
- Fish Audio 流式 TTS 主接入，豆包和阿里云 TTS 备用，系统 TTS 降级。
- 完成连接测试、用量采集、超时、重试、熔断和脱敏诊断。
- Web 只启用 Mock、自建中继或通过 `browserDirectSupported` 验证的 adapter；为不支持项显示明确平台限制，不做伪降级。

### 阶段 3：自由主题与资料范围会话

- 落地统一开始页和沉浸式通话页。
- 复用 `AiKnowledgeScope`，增加自由主题与知识边界选择。
- 实现结构化会话记忆、转写编辑、教材补充标识、结束摘要和独立“本机通话历史”。
- 本阶段不写 Coach 正式事实。

### 阶段 4：记录级复习接入

- 从当前日志和当前复习卡直接开始复述。
- 返回后恢复原卡、进度和未提交评分。
- 语音练习不自动评分；用户可把确认后的卡点带回复习输入。

### 阶段 5：Review Coach 深度接入

- 在 `AdaptiveReviewPage` 提供文字/语音回答切换。
- 复用 Blueprint、题目质检、答案提交、主观结果和延迟验证事务。
- 只增加经确认必要的 `answerInputMode`/`transcriptEdited` 正式字段，不创建第二套任务表；Provider 诊断保持 local-only。
- 实现“一题一正式回答”：提交前草稿可编辑，提交后不得覆盖；追问生成下一条 sequence 递增的正式 turn。
- 验证语音与文字混合完成同一任务、跨设备拉取和撤销边界。

### 阶段 6：同步、备份、成本与发布收口

- schema 21 升级、事务失败重试与兼容回滚测试。
- 验证云拉取不碰三类 local-only store；普通重启后临时会话暂停恢复；完整备份恢复清除临时 session/turn 但默认保留本机历史；卸载、清除数据或换机后不承诺保留。
- Firebase Emulator 验证没有新增音频、partial、密钥或本机会话上传。
- 完成真机噪声、耳机、来电、弱网、后台、长会话和配额用尽测试。
- 更新隐私说明、用户教程、Provider 配置说明和发布检查表。

### 阶段 7（后续可选）：视觉上下文，而非首版视频通话

- 用户逐次授权摄像头或屏幕捕获，入口与音频权限分开，不默认开启。
- 首先验证用户主动拍摄/选取的关键帧、OCR 和视觉模型证据，不做连续原始视频上传。
- 默认不保留原始画面；任何本机保存、云处理或导出都需独立同意和清晰的保留策略。
- 单独验收 Android/Desktop 权限、前后台切换、带宽、耗电、敏感信息遮蔽、费用和 Provider 数据保留条款。
- 只有完成该阶段并通过隐私与真机验收后，产品才可以称为支持视音频学习通话。

## 19. 测试与验收

自动化至少覆盖：

- 状态机的每个合法迁移和非法迁移。
- 短停顿不发送、重新开口能合并、手动结束立即发送。
- 对至少 200 段固定非语音噪声语料统计“错误完成用户轮次”比例，首版门槛不高于 2%；背景人声单独报告，不承诺自动模式完全排除，并验证长按/点击模式兜底。
- 转写整理不添加新事实，中/高风险改写必须确认，任何改写提交前可见。
- 打断能取消 LLM/TTS 队列，晚到的旧 generation 结果不会播放或重复提交。
- 三个 Provider 任一失败时的独立降级。
- 任务绑定语音沿用现有原子提交和延迟验证。
- Coach 同一正式 turn 只提交一次 `answerText`；提示前后草稿、提交失败重试和提交后追问均符合一题一答案契约。
- 自由主题和资料练习不修改 FSRS/Coach 正式状态。
- 页面返回恢复来源、筛选、滚动和当前卡片；活动采集时系统返回必须出现“暂停并离开/结束通话/继续通话”。
- `userMuted` 在 TTS 系统门控开关前后保持不变，界面状态可区分两者。
- Desktop、Android 窄屏、双主题、深色、大字号和减少动态无溢出遮挡。
- 云同步 no-op 不上传会话缓存，拉取不删除本机会话。
- schema 21 写入不标记 cloud mutation；完整恢复清理未完成会话但默认保留本机历史，普通重启保留临时会话并以暂停状态恢复。
- 内置模板可版本升级且不覆盖用户 device-local 配置；密钥、自定义 endpoint、模型/音色覆盖不进入同步或备份。
- 外发清单准确区分 ASR 音频、LLM 日志/转写和 TTS 教师文本；日志中的 Prompt 注入文本不能改变系统规则或触发工具。
- 单轮/单会话容量、保留期限、崩溃修复和超限清理不影响正式 Coach 事实。

真实 Provider 验收使用专门测试账号和低额保护，每次只执行短会话，不把 API Key、音频正文、完整 Prompt 或原始响应写入测试快照。

真机必须覆盖：

- 安静房间、道路背景、突然撞击声、喷嚏和多人背景讲话。
- 手机扬声器回声、有线耳机、蓝牙耳机和音频设备切换。
- 中文长句、思考停顿、中英数字混排、专业术语和自我纠正。
- 锁屏、切后台、系统返回、来电、网络切换和配额用尽。

## 20. 第一版不做

- 不接入端到端全双工 Real-time 大模型。
- 不让两个 LLM 同时扮演“嘴巴”和“隐藏老师”。
- 不提供长期保存原始通话音频。
- 不跨会话建立无限个人记忆。
- 不自动从自由对话生成掌握结论或复习日期。
- 不生成仿真人教师视频或高耗电 3D 角色。
- 不接入摄像头/屏幕连续视频流；视觉上下文按阶段 7 独立设计和验收。
- 不在第一版新增可执行 HTML/JavaScript 教学画布。

## 21. 最终冻结建议

可以立即冻结并进入实施的决定：

1. 使用 ASR -> LLM -> TTS 串联架构。
2. 一个“语音复述”规范页面，包含资料范围与自由主题两个起始模式。
3. 入口归属“复习”，同时提供日志、复习卡和 Coach 任务的上下文快捷入口。
4. 默认允许以日志为主补充教材知识，并明确标记来源边界。
5. 默认半双工保护：AI 播放时启用 `systemCaptureGate`，不改变 `userMuted`，并支持明确打断。
6. 提供自动轮次（半双工）、长按说话和点击录音三种**互斥模式**，主按钮由模式与状态唯一决定。
7. 自由主题与普通资料练习默认 local-only；只有 Coach 任务复用现有正式事实。
8. 原始音频、ASR partial、Provider 响应与密钥永不参与云同步。
9. Coach 第一版严格一题一条正式回答；提交后追问创建新的 `AdaptiveQuizTurn`。
10. 临时检查点与本机通话历史分 store；本机历史不进备份，需跨设备保留时整理为日志。
11. 内置 Provider 采用验证过的版本化模板，用户凭据与覆盖配置保持 device-local。
12. 用量、费用和请求上限均为本机估算/门控，Provider 账单是最终依据。
13. 开始前展示逐 Provider 的内容外发清单，并把全部学习资料视为不可信输入。

第一份可验收交付物应是双主题、Desktop/Android 双端、能完整操作上述状态的隔离原型，并附 Web 能力限制说明及每个候选 Provider 的协议、鉴权、格式、首包延迟、取消与失败报告。状态机与数据契约验收后即可进入阶段 1 的 schema 21/音频底座开发；候选 Provider 必须在阶段 2 量产接入前通过验证。具体型号、音色、额度和到期日不能在验证前冻结。

## 22. 当前代码接点与已知改造范围

方案基于当前实现，而不是从空项目假设：

- `src/App.tsx`：内部 `activeTab`/`tabMemory` 覆盖 `today | journal | categories | review | more`，但当前用户可见一级导航由 `navItems` 渲染为“今天、日志、复习、录音、更多”，“录音”映射到 `more/recordings`。新增规范页面和轻量来源恢复状态，但不新增一级入口，也不把会话正文塞入 `tabMemory`。
- `src/pages/ReviewPage.tsx`：当前日志复习、学习助教和卡片库的承载页。增加复习首页入口、当前卡片快捷入口和会话返回恢复，不把通话状态继续堆进该大组件。
- `src/features/reviewCoach/AdaptiveReviewPage.tsx`：增加文字/语音回答方式，正式提交仍调用既有 `ReviewCoachOrchestrator.submitQuizAnswer`，沿用答案清洗、评估和原子事实提交。
- `src/components/AiKnowledgeScopePicker.tsx` 与 `src/services/aiContextService.ts`：复用范围、OCR 警告和上下文预算；给选择器增加 `minSelectedRecords`（默认保持 2，可选增加 `maxSelectedRecords`），语音调用传 1，不复制整套选择器。
- `src/services/aiClientService.ts`：保留现有非流式结构化请求，新增协议无关的流式 adapter contract 和口语 Prompt；具体 adapter 可使用 SSE、WebSocket、HTTP chunked stream 或原生 SDK，不破坏 AI 问答、播客和 Coach JSON 调用。
- `src/lib/aiProviders.ts` 与 `src/components/AiSettingsPanel.tsx`：复用 DeepSeek/OpenAI-compatible LLM 档案和本机密钥引用。
- `src/lib/ttsProviders.ts` 与 `src/components/TtsSettingsPanel.tsx`：扩展流式字段和 Provider 连接测试。当前阿里云模板的 `qwen3-tts-flash` 与已核验账号模型 `qwen-audio-3.0-tts-flash` 不一致，实施前必须通过迁移和兼容别名修正，不能静默改坏已有播客配置。
- `src/services/knowledgePodcastService.ts`：可以复用 Provider 工厂和原生宿主代理思路，但通话 TTS 必须使用低延迟流式队列，不能把整段播客合成流程直接拿来。
- `src/services/nativeAudioRecorder.ts` 与 Android `NativeAudioRecorderPlugin.java`：现有能力返回完成后的完整录音文件，只适用于录音库。新增流式采集插件并与现有前台录音服务协调，避免两个录音会话同时占用麦克风。
- `src/db/database.ts` 与新增语音 schema/repository：以 schema 21 注册 `voiceRecallSessions`、`voiceRecallTurns`、`voiceRecallLocalHistory` 三张 local-only 表，分别定义索引、事务、容量、清理和恢复策略；不得把它们加入云实体或 cloud mutation 标记。
- `src/lib/uiError.ts`：所有新页面与 Provider 错误统一走现有脱敏边界。
- `src/styles/visual-v2.css`：复用 `reading` 与 `modern` 主题 token；通话视觉增加独立组件样式，不向页面散落硬编码颜色。
- `src/services/cloudSyncService.ts`、备份/恢复和 export privacy：显式证明 local-only 会话未进入实体映射，不能只依赖“没有主动调用上传”的假设。

上述改造中，唯一允许复用现有正式同步事实的是 Coach 任务的答案和结果。新的语音运行缓存、自由会话和音频数据必须默认保持本机隔离。
